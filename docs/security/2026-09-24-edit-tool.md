# Security record — Edit replaces a string in a file, 24 September 2026

**Subject:** `Edit` replaces one exact occurrence of a string in a file, or every occurrence with
`replace_all`, once the user approves the path and both strings. It changes what
[the write tool](2026-09-24-write-tool.md) can change: a file read in part, redacted, or with CRLF
line endings, which Write refuses. It shares Write's path rules, fence, stamps and rename. The
living model is [security-model.md](../security-model.md).

## What can change

Any file Write could replace, read in this chat and unchanged since, but read whole or not: a
stamp that matches the file's bytes is enough. The change is bounded by the two strings — the text
that goes and the text that replaces it — and nothing else in the file moves. Edit never creates a
file (`TestEditRefusesByInputUnasked`, `TestEditRefusesWhatItDoesNotChange`).

## The request is the two strings

**Every Edit that can run is asked** (`TestEditAsksOnTheNameAlone`). The request draws *Edit this
file?*, the path as a write's, then *Replace* over the old string and *With* over the new, each
drawn as a write's content is: through `VisibleText`, every `\r` and each space or tab that ends a
line spelled, folded on its own past 2,000 characters or 24 lines, with Approve waiting on both
(`draws the path and both strings as text, with two buttons`, `spells each \r and the whitespace
ending a line`, `folds each long string and holds Approve until both are shown`).

**A string's edges are named.** A newline at either end decides whether the edit joins or splits
lines, and a `<pre>` draws neither, so a line under each string says whether it starts or ends
with one (`names the newlines at the edges of each string`): `"x: 1\n"` replaced with `"x: 2"`,
which joins two lines, reads as a dropped newline. An empty new string reads *The text will be
deleted.* A tab against spaces mid-line, or a change of indent, still draws as the same text, so
two strings equal with every `\s` removed carry *The two differ only in whitespace.* (`names a
change in whitespace alone`). `replace_all` adds *Every occurrence in the file.*

**The request does not show where the match is.** The user approves a unique match, not a located
one: without `replace_all` a string that matches twice is refused, and so is one whose single
match another overlaps (`TestEditRefusesAMatchThatIsNotUnique`). With `replace_all` the count is
not known until the edit runs; the result names it (`TestEditReplacesAll`).

**A call that can only fail is not asked.** `check` refuses, before touching anything, an empty
`old_string`, one equal to `new_string`, and a `new_string` holding a NUL byte or `[redacted]`,
the mark Read shows in place of a secret, so Edit never writes the mark as text.

## A stamp, not a whole read

An edit needs the chat's stamp of the file, matching the bytes now (`TestEditNeedsAMatchingStamp`),
but not a `Whole` one. So after a partial Read, `replace_all` also changes occurrences the model was
never shown; the user approved every occurrence, and the count comes back. A successful edit
stamps the new bytes, `Whole` only when the old stamp was and the strings went in as the model sent
them (`TestEditSetsTheStamp`).

## One conversion, and only in a CRLF file

Read shows LF for CRLF, so in a file whose every line break is `\r\n` the model's LF strings are
converted to CRLF before matching, and the file stays CRLF (`TestEditMatchesLFInACRLFFile`). The
gate reads nothing on disk, so the request draws the LF strings the model sent while the file gets
CRLF. A file that mixes endings is matched exactly, and nothing else is folded: a tab never
matches spaces (`TestEditFoldsNothingElse`). Two strings the conversion makes equal are refused
(`TestEditRefusesANoOpAfterTheFold`).

## Bounded work

The result's size is computed from the count before it is built, and an edit past 8 MiB is
refused (`TestEditRefusesAnOversizedResultBeforeBuildingIt`). The uniqueness check stops at a
second match rather than walking every overlap, which a long repetitive string would make
quadratic on a goroutine the cancel cannot stop (`TestEditUniquenessIsLinear`). The file work runs
where the call can leave it, and a stuck edit answers the cancel and changes nothing
(`TestAStuckEditHonoursTheCancel`).

## The write

Edit writes through `fileguard.Replace` after `fileguard.Replaceable`, so everything the write
tool's record says of the owner, the group, the permissions and the rename holds here
(`TestEditKeepsTheModeAndGroup`, `TestEditRefusesWhatItCannotWrite`, `TestEditIsARename`). The data
directory is fenced by name and through a link, and a link in the last component is refused with
its target (`TestEditRefusesTheDataDirThroughALink`, `TestEditRefusesALinkNamingItsTarget`).

## Residual

Write's, and two of Edit's own:

- **The request draws LF strings in a CRLF file**, where the file gets CRLF.
- **Matching runs on the raw file**, so whether an approved `old_string` matched tells the model
  something about text Read redacted — one approved probe per answer.
- **A file that holds `[redacted]` as its own text** cannot be edited with it kept as context.
